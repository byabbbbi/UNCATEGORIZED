# UNCATEGORIZED AI 기술 문서

**[플레이](https://byabbbbi.github.io/UNCATEGORIZED/)** · **[저장소](https://github.com/byabbbbi/UNCATEGORIZED)**

UNCATEGORIZED의 LLM 생성은 한 번으로 끝나지 않는다. 플레이 중 기둥이 붕괴하면 해당 범주의 규칙 문자열이 생성용 시스템 프롬프트에 누적된다. 조합 캐시 키에도 붕괴·오염 상태가 들어가므로 플레이가 이후 생성 환경을 바꾸는 구조. 적용된 규칙은 우측 `생성 규칙` 패널에 그대로 공개된다.

## 1. 시스템 구성

React 19 + TypeScript 6 + Vite 8 기반 정적 SPA. Zustand는 런 상태, `localStorage`는 진행 저장, `idb-keyval`은 조합 결과 캐시를 담당한다. 배포된 브라우저 번들에는 API 키가 없으며, 런타임 LLM 호출은 프록시로 `messages` 배열만 보낸다.

Worker의 `MODEL_ID`와 호출 제한은 서버 환경 변수·서버 코드가 강제한다. 특정 모델명은 문서에 명시하지 않는다. 모델 선택과 키 값은 클라이언트가 결정하거나 읽을 수 없는 영역이며, 비밀 값도 저장소와 문서에서 제외된다.

```text
generate(A, B, world)
  1. HARD_TABLE 406건
  2. IndexedDB 캐시
  3. 프리로드 JSON
  4. 프록시 경유 런타임 LLM
  5. LEXICON 로컬 폴백
```

## 2. 5단 생성 체인

### 2.1 1단계: 하드테이블 406건

`collapsed.length === 0`일 때 정렬된 조합쌍으로 `HARD_TABLE`을 먼저 조회한다. 활성 오염 유무는 조회 조건이 아니다. 시작부터 오염이 승격된 오늘의 세계도 붕괴 기둥이 없다면 하드테이블을 사용한다.

오염이 없으면 테이블 결과를 즉시 반환한다. 활성 오염이 있으면 현재 캐시 키를 해시한 `mulberry32`로 30%를 판정하고, 선택된 오염 키워드를 결과 이름 앞에 붙인 뒤 별도 IndexedDB 항목으로 저장한다. 같은 조합·붕괴·오염 상태에서 재현되는 하드테이블 후처리이며 API 호출은 없다.

### 2.2 2단계: IndexedDB 캐시

캐시 키는 [`src/generation.ts`](../src/generation.ts)의 아래 세 요소를 `|`로 잇는다.

```text
정렬된 입력 이름 쌍 | 정렬된 붕괴 기둥 목록 | 정렬된 활성 오염 목록
```

코드 표현은 `pairKey(a, b)|collapsed.sort()|contaminants.sort()`이며 `era`는 캐시 키에 포함되지 않는다. 세계의 붕괴·오염 상태가 달라지면 같은 입력도 별도 결과를 사용한다. 세 요소가 같을 때만 저장된 결과를 재사용.

### 2.3 3단계: 프리로드 JSON

IndexedDB에 값이 없으면 `src/data/preload.json`에서 같은 캐시 키를 조회한다. 적중 결과는 IndexedDB로 옮겨 이후 요청에서 먼저 재사용한다. 프리로드 생성 스크립트의 pillar enum 역시 여덟 기둥.

### 2.4 4단계: 프록시 경유 런타임 LLM

프리로드까지 빗나가면 `buildMessages()`가 현행 세계 상태·총량 `T`·출력 스키마·금지 규칙·few-shot 3개를 구성한다. 브라우저에서 프록시로 보내는 값은 이 `messages`뿐이다.

각 API 시도의 타임아웃은 20,000ms. 첫 응답이 명시적 거부이고 JSON이 없으면 검열 개념 `███`로 저장한다. JSON 파싱·정규화 뒤에는 `isBadName()`이 이름을 검사한다. 부적절하다고 판정된 직전 이름을 거부 사유로 프롬프트에 넣어 정확히 한 번 다시 호출하는 방식. 리롤 응답도 거부되거나 품질 검사에 실패하면 폴백으로 내려가며, 한 조합의 API 시도는 최대 2회다.

품질 검사의 기준은 공백 제외 10자, 최대 3어절, 이상 문자와 조어, 알려진 명사 포함률, 입력 연관성. 관계 기둥이 무너지지 않았고 두 입력이 서로 다른 개념이면, 공백 없는 결과가 양쪽 입력의 `headNoun()`을 모두 포함할 때 concat으로 판정한다.

### 2.5 5단계: LEXICON 로컬 폴백

네트워크 오류, 20초 타임아웃, JSON 파싱 오류와 두 번째 품질 검사 실패는 `fallbackGenerate()`가 받는다. 입력 이름 쌍 해시를 `mulberry32` 시드로 사용하며, 핵심 명사를 결합하되 길이·어절 제한을 넘으면 70개 `LEXICON`에서 아직 소유하지 않은 이름을 고른다. 마지막에는 공백 제외 10자·최대 3어절 제한을 다시 적용.

폴백에도 세계 상태가 코드로 반영된다. 관계는 두 핵심 명사를 공백 없이 결합하고, 본질·영겁은 수식어를 앞에 붙이며, 측정은 번호를 붙이고, 실재는 40% 확률로 문자열을 뒤집는다. 좌표는 장소형 단어, 소유는 `주인`, 인과는 `○○가 남긴 것` 형태. 활성 오염 역시 30% 확률로 이름 앞에 붙는다.

## 3. 실패·정규화 처리

| 단계 | 처리 |
| --- | --- |
| 응답 추출 | 코드펜스를 제거하고 첫 `{`부터 마지막 `}`까지만 JSON으로 파싱한다. |
| 스탯 | 네 값을 0~100으로 clamp하고 비율을 다시 계산해 합이 코드가 정한 `T`가 되도록 반올림 오차를 보정한다. |
| 이름 | 공백을 정리하고 최대 3어절, 공백 제외 10자로 제한한다. 하드테이블·API·폴백·오염 후처리에 같은 유틸을 쓴다. |
| 이모지 | `Intl.Segmenter('ko', { granularity: 'grapheme' })`의 첫 그래핌 하나만 남긴다. 미지원 시 첫 코드 포인트로 폴백한다. |
| 기둥 | `substance|quantity|quality|time|relation|place|state|action` 밖의 값은 여덟 기둥 중 하나로 대체한다. |
| 오염·연대기 | 오염은 첫 어절 8자, 연대기는 90자로 제한한다. |
| 거부 | JSON 없는 명시적 거부를 `███`로 바꾼다. 최초 발견이면 정합성 3을 회복하고 대장에 남긴다. |

## 4. 역할 경계

| 주체 | 결정하는 것 |
| --- | --- |
| 코드 | 총량 `T`, 기본 파괴력 `D`, 정합성 감소와 파편, 시대 배율, 기둥 안정도·붕괴, 오염 승격, 사건 배정·진행·보상, 세 엔딩, 생성 체인·타임아웃·리롤·캐시 키, 하드테이블, 폴백, 응답 정규화와 검열 차단을 결정한다. |
| AI(런타임) | 4단계가 실행된 경우 개념 이름·이모지, `T` 안의 네 스탯 배분 제안, 소속 기둥, 오염 키워드, 등장 연대기 한 문장을 단일 JSON으로 제안한다. 코드가 길이·그래핌·enum·합계를 다시 강제한다. |
| 플레이 | 시작 모드, 어떤 두 개념을 조합할지, 어떤 카드를 복제·보관할지, 어느 기둥에 언제 선포할지, 시대를 언제 마감할지를 결정한다. 그 선택으로 붕괴 규칙과 활성 오염, 즉 이후 프롬프트가 달라진다. |

핵심 수식은 [`src/game/formulas.ts`](../src/game/formulas.ts)의 계산 코드를 그대로 옮겼다.

```ts
return Math.min(60 + depth * 12, 80 + era * 20)
return (chaos * plausibility) / 100
return 4 + Math.max(0, chaos - plausibility) / 4
const shardsGained = Math.floor(D / 5)
```

## 5. 세계 상태의 프롬프트 주입

### 5.1 붕괴 규칙 8종 전문

[`src/data/rules.ts`](../src/data/rules.ts)의 문자열 원문. 기둥이 붕괴하면 `collapsedRules`에 추가되어 시스템 프롬프트와 우측 패널에 그대로 쓰인다.

| 기둥 | 삽입되는 규칙 |
| --- | --- |
| SUBSTANTIA · 실재 | 개념을 발음이 비슷한 다른 사물로 바꿔 부를 수 있다. 배(선박)는 배(과일)다. |
| QUANTITAS · 측정 | 모든 결과물 이름에 3~4자리 일련번호를 붙인다. 번호는 매번 커진다. |
| QUALITAS · 본질 | 수식어를 어울리지 않는 명사에 붙인다. 수식어가 수식어를 수식해도 좋다. |
| TEMPUS · 영겁 | 서로 다른 시대의 것을 한 개념 안에 공존시킨다. |
| RELATIO · 인연 | 서로 무관한 두 개념을 한 단어로 압축하라. 언어를 섞어도 좋다. |
| LOCUS · 좌표 | 둘 이상의 장소나 지형을 한 이름으로 합쳐라. 모순되어도 좋다. |
| HABITUS · 소유 | 소유 관계를 뒤집어라. 사물이 사람을 지니게 하라. |
| ACTIO · 인과 | 행위의 주체와 대상을 뒤바꾸거나 불명확하게 하라. |

### 5.2 오염

처음 발견한 개념의 `contaminant`가 같은 키워드로 3회 누적되면 활성 오염이 된다. API 단계에서는 프롬프트마다 30% 확률로 활성 키워드 하나를 골라 오염 지시를 넣고, 로컬 폴백에도 30% 분기를 코드로 적용한다. 하드테이블의 30% 후처리는 캐시 키 기반 결정적 판정이라는 점이 다르다.

오늘의 세계는 시작할 때 한 키워드의 누적값을 이미 3으로 설정한다. 첫 조합부터 오염 세계지만, 붕괴 기둥이 없다면 1단계 하드테이블을 계속 쓸 수 있다.

## 6. 생성 프롬프트 전문

[`buildMessages()`](../src/generation.ts)의 `system` 템플릿 본문 원문. `${…}`는 TypeScript 템플릿 보간이며, 실제 호출에서는 총량·붕괴 규칙·오염·리롤 사유와 예시 스탯으로 치환된다.

```text
당신은 개념 조합 판정기다. 두 개념을 합쳐 새 개념 하나를 만든다.
반드시 JSON 객체 하나만 출력한다. 마크다운, 설명, 인사 금지.

[세계 상태]
무너진 범주의 규칙 — 결과 이름에 반드시 반영하라:
${rules.length ? rules.map((r) => '- ' + r).join('\n') : '- 없음. 평범하고 자연스러운 결과를 낼 것.'}
${roll ? `오염 지시: 결과 이름에 '${roll}'${josa(roll, ['을', '를'])} 자연스럽게 섞어라.` : ''}
${rejectName ? `\n직전 결과 '${rejectName}'${josa(rejectName, ['은', '는'])} 부적절했다. 더 평이하고 이해하기 쉬운 실존 명사로 다시 만들어라.` : ''}

[출력 형식]
{"name":"한국어 2~10자(공백 제외). 자연스러우면 띄어 써도 좋다. 최대 3어절","emoji":"이모지 정확히 1개. 두 개 이상 쓰지 마라","chaos":0,"plausibility":0,"narrative":0,"contagion":0,"pillar":"substance|quantity|quality|time|relation|place|state|action","contaminant":"명사 1개","chronicle":"등장 기록 한 문장. 건조한 행정 문체."}

[규칙]
- chaos+plausibility+narrative+contagion 합은 정확히 ${T}
- chaos: 세계의 규칙을 얼마나 어기는가
- plausibility: 그런데도 얼마나 그럴듯한가. 노골적으로 강해 보이려는 이름("무한","전능","신" 남발)은 반드시 낮게
- pillar: 이 개념이 흔드는 범주 하나
- 실존 국가·정치인·실존 인물 금지
- 실존하거나 즉시 이해 가능한 명사를 조합하라. 의미를 알 수 없는 조어·낱말 잇기를 만들지 마라
- 결과 이름에 두 입력의 단어를 모두 넣지 마라. 하나만 남기거나, 둘 다 버리고 새로운 사물명을 만들어라.
- 두 입력 이름을 그대로 이어붙인 결과는 실패로 간주한다
- A와 B가 같은 개념이면, 반복이 아니라 그것이 쌓이거나 심화된 하나의 사물을 만들어라 (점토+점토=벽돌)

[예시]
입력 A: 빵집, B: 숫자
{"name":"베이커리 4395호점","emoji":"🥐","chaos":${ex1.c},"plausibility":${ex1.p},"narrative":${ex1.n},"contagion":${ex1.g},"pillar":"quantity","contaminant":"지점번호","chronicle":"1호점부터 4394호점까지의 위치를 아는 자는 없다."}

입력 A: 점토, B: 점토
{"name":"벽돌","emoji":"🧱","chaos":${ex2.c},"plausibility":${ex2.p},"narrative":${ex2.n},"contagion":${ex2.g},"pillar":"substance","contaminant":"점토","chronicle":"점토가 쌓여 벽돌로 등재되었다. 규격은 추정이다."}

입력 A: 늪, B: 안개
{"name":"늪 안개","emoji":"🌫️","chaos":${ex3.c},"plausibility":${ex3.p},"narrative":${ex3.n},"contagion":${ex3.g},"pillar":"quality","contaminant":"습기","chronicle":"늪과 안개가 만나 늪 안개로 등재되었다. 농도는 추정이다."}
```

`user` 메시지 생성 코드도 그대로 옮겼다. `\n`은 실제 요청에서 세 줄로 바뀐다.

```ts
{ role: 'user', content: `A: ${a.name}\nB: ${b.name}\n총량 T: ${T}` },
```

## 7. 결정성과 비용 경계

- 하드테이블·오염 후처리, 로컬 폴백, 오늘의 세계와 사건 순서는 시드 기반.
- API의 이름 생성과 오염 지시 30% 추첨은 호출 시점에 이루어지지만, 성공 결과는 세계 상태가 포함된 IndexedDB 키에 저장된다.
- 하드테이블과 캐시·프리로드 적중에는 API 호출이 없다. API 단계는 정상 1회, 이름 품질 리롤이 필요할 때만 최대 2회다.
- 신의 대사는 여덟 기둥 × 세 단계의 수기 풀에서 고르며 API를 쓰지 않는다.
- 분실물 보관소의 개념과 등급표도 수기 데이터. 보관소 이름에 붕괴 변형이 적용될 수 있지만 LLM 호출은 없다.

## 8. 검증 명령

```bash
npm run build
npm run validate:combos
```

`validate:combos`의 검사 범위는 하드테이블 항목 수, 이름 길이·구체 명사성·그래프 도달성·통계 범위, 이모지 그래핌 1개 조건.
